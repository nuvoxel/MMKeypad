Media Keypad Intercom

SIP intercom endpoint for a NuVoxel Media Keypad

GitHubBuy me a coffee

This driver gives a NuVoxel Media Keypad its intercom endpoint: SIP registration, intercom calls, announcements and door-station handling. It is a companion to the Media Keypad driver — one of each, per panel.

It is a separate driver on purpose. A driver's proxy set is frozen once installed, so folding an intercom proxy into the keypad driver would corrupt every project that already had one. Add both drivers, then run Find and Bind Intercom on the keypad driver to link them.

Installation

  • Add the Media Keypad driver first and let it pair with the panel.
  • Add this driver, in the same room.
  • On the keypad driver, run Actions → Find and Bind Intercom. It prefers an instance in its own room.
  • The Communications agent picks the endpoint up on its own. Registering is not the same as being callable — if it registers but callers get "Can't find user", the agent has not re-scanned yet.

Door Actions

When a door station calls the panel, the call screen can show up to two extra buttons — typically Unlock and Open Gate.

Door Action 1 LabelText for the first button, e.g. Unlock. Blank = no button.
Door Action 2 LabelText for the second button, e.g. Open Gate. Blank = no button.

The buttons do nothing by themselves. Give them a label here, then in Programming handle this driver's Door Action 1 / Door Action 2 events and drive whatever you want — a lock relay, a gate, a scene. The LAST_DOOR_PEER variable holds which door station the call came from, so one event can serve several doors.

They only appear on calls from a peer the Director reports as a door station, never on a room-to-room intercom call.

Actions

Re-register SIPForce a fresh SIP registration and re-push the account to the panel. This is the right place to fix SIP — the keypad driver's Re-link Intercom only re-announces the pairing.

Events

Door Action 1 / 2Fired when someone taps that button on a door-station call. Read LAST_DOOR_PEER to know which door.

The standard intercom properties

The Properties page above the driver's own settings is Control4's stock intercom endpoint page (Appearance, Behavior, Audio Control, SIP Information). Those are handled by the intercom proxy, and the ones that apply here work as they do on any Control4 endpoint — Play Door Chime, Do Not Disturb, Auto Answer, Monitor Mode, and the ringer / speaker / microphone levels all reach the panel.

Custom Button 1 and 2 on that stock page are not wired up in this driver — use Door Action 1 / 2 above instead. Video-specific options (Send Video, Alternate Camera) do nothing: these panels are audio-only.
